# Setup Guide

This covers getting Blaze AI running from scratch on a Mac Mini (or MacBook). The stack is Ollama + Open WebUI + Docker.

---

## Hardware

The Stage 2 deployment runs on a Mac Mini M4 Pro with 48GB unified memory. That's enough headroom to run Phi-4 (14B) comfortably alongside Docker and Open WebUI with multiple simultaneous users.

Minimum to run this at all: 16GB RAM. 8GB works for testing but will be slow under any real load.

---

## Step 1: Install Ollama

Download from [ollama.com](https://ollama.com). Run the installer. Then pull the model:

```bash
ollama pull phi4
```

This downloads about 9GB. Verify it works:

```bash
ollama run phi4
```

Type something, confirm you get a response, then `/bye` to exit.

---

## Step 2: Install Docker

Download Docker Desktop from [docker.com](https://docker.com). Install and open it. Let it finish starting before continuing.

In Docker Desktop → Settings → Resources, allocate at least:
- CPU: 4 cores
- RAM: 8GB (more if your machine has it to spare)

---

## Step 3: Deploy Open WebUI

Run this in Terminal (one command):

```bash
docker run -d -p 3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main
```

Then open `http://localhost:3000` in your browser. Create an admin account — this is local only, nothing goes to the internet.

---

## Step 4: Connect Open WebUI to Ollama

Go to Open WebUI → Settings → Connections. Set the Ollama URL to:

```
http://host.docker.internal:11434
```

Save. Go back to the main chat and check the model dropdown — you should see `phi4` listed.

---

## Step 5: Create the Blaze AI model profile

In Open WebUI: **Workspace → Models → + New Model**

- Name: `Blaze AI`
- Base model: `phi4`
- System prompt: paste the contents of `system_prompt.md`

Save it. This is the version teachers will use — they select "Blaze AI" from the dropdown, not the raw `phi4` model.

---

## Step 6: Load the RAG knowledge base

In Open WebUI: **Workspace → Knowledge → + New Collection**

Name it something like `Concordia Documents`. Upload your school documents:
- Policy and handbook PDFs (downloaded manually from the Employee Center)
- Atlas curriculum exports
- Text files generated by `canvas_sync.py`

When teachers use Blaze AI, they reference this collection by typing `#` in the chat to attach it, or you can make it the default in the model profile.

---

## Step 7: Run the Canvas sync (optional)

See `canvas_sync.py`. Set your Canvas API token as an environment variable:

```bash
export CANVAS_TOKEN=your_token_here
python canvas_sync.py
```

This exports your course content to `canvas_export/`. Upload those files to the knowledge base.

---

## Step 8: User management

For the pilot, create accounts manually and disable open registration:

**Create accounts:** Settings → Admin Panel → Users → + Add User

**Disable open registration:** Settings → Admin Panel → General → toggle off "Enable New Sign Ups"

Share the Mac Mini's local IP address (e.g., `http://192.168.1.XX:3000`) with pilot teachers. They'll log in with the credentials you set.

---

## Keeping it running

Open WebUI's Docker container is set to `--restart always`, so it starts automatically on boot. Ollama also installs a background service that starts on login.

To assign the Mac Mini a static local IP (so the address doesn't change), go to your router's admin panel and reserve the Mac Mini's MAC address.

---

## Updating the model

To swap models (e.g., upgrading to a newer release):

```bash
ollama pull phi4:latest   # or whatever the new tag is
```

Then update the base model in the Blaze AI profile in Open WebUI.
